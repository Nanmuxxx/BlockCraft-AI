# 演示前检查清单（Demo Day Checklist）

> 使用方法：演示前 30 分钟从头到尾执行一遍，全部打勾才开始正式演示；任何一项失败且 10 分钟内修不好，切换到"降级口径"（见文末）。
> 版本基线：**origin/main @ 4a95cae**（2026-10-19 浏览器 QA 15/15 PASS）；标注"（QA 已验证）"的项当日只需快速复核。

## 1. 环境与进程

- [ ] 演示机 Node >= 22.16（`node -v`；server engines 要求，QA 在 Node 24.21 实测通过）
- [ ] 依赖已安装：根目录 `npm install` 完成；**server 已构建**（`npm --prefix server run build`——生成 `server/.generated/`，QA 实测缺失会导致后端无法启动）
- [ ] 后端已启动：`npm --prefix server start`，监听 `127.0.0.1:3001`
- [ ] `curl http://127.0.0.1:3001/api/health` 返回 `{"status":"ok"}`
- [ ] 前端已启动：`npm run dev -- --host 127.0.0.1`，记下 Vite 实际端口（默认 5173；`/api` 自动代理到 3001，QA 已验证）
- [ ] 浏览器打开 `http://127.0.0.1:<端口>/ai-create` 正常显示
- [ ] （若演示 v1 真实生成）部署授权已由 server 侧注入（401 授权门，QA 已验证未授权时诚实报错）

## 2. 密钥与费用安全

- [ ] **明确本次演示口径**：离线主线（可信番茄钟，零费用零密钥）或已授权+已配密钥（真实 v1 生成）——二选一，与台词一致
- [ ] 离线主线：确认来源标注"离线固定 Fixture，非真实 DeepSeek 调用"出现在应用页（QA 已验证）
- [ ] 若配了密钥/授权：凭证只在 `server/.env` 或部署注入；确认投屏内容不含该文件、终端日志、环境变量输出
- [ ] 断网预案：番茄钟离线主线与 `/app-renderer` 示例均不需要外网（QA 已验证）

## 3. 演示路径预走（约 90 秒，快速版）

## 5. 演示中即时应对

| 症状 | 处置 |
| --- | --- |
| 点"加载离线番茄钟"没反应 | 刷新重试（本地加载不应失败）；仍失败 → 降级口径 |
| v1 生成报 401/502 | 预期行为（授权门/CRLF 环境自检，见 QA 报告 F1）——按"诚实报错+保留数据"讲解，切回番茄钟主线 |
| 出现"生成失败…已保留"alert | 正常健壮性行为，直接讲解"失败保留旧应用" |
| Mochi 面板发不了消息 | 预期（AI 修改未启用），按台词讲诚实边界 |
| 页面刷新后数据没了 | 预期（仅内存），可补一句"可导出 React 项目带走成果" |
| Vite 端口不是 5173 | 用终端实际端口，不影响功能 |
