# Runtime protocol v1

Only the single Supervisor assigns a READY task to a UUID worker_id. Each task has immutable id, issue, kind, base SHA (40 lowercase hex), normalized literal file scopes, dependencies, priority, acceptance criteria, risk gate and explicit worker_id. No glob/absolute/traversal/symlink scope aliases. Case-folded prefix overlap reserves directories conservatively across macOS/Windows. READY assigned tasks reserve ownership too; conflicting allocation is rejected transactionally.

Task states: READY → CLAIMED → RUNNING → REVIEW → ACCEPTED or REWORK. Any active task may become BLOCKED. Worker states: READY, RUNNING, BLOCKED, OFFLINE, DONE. DONE is a worker receipt, never task acceptance. Reports contain task/worker/session, base/head/test SHA, start/finish, command arrays, bounded redacted stdout/stderr, exit codes, scope diff and artifact hashes. Every mutation appends an event with actor, timestamp, task/issue/SHA, prior/new state, reason and evidence.

SQLite BEGIN IMMEDIATE serializes claim and assignment. A Worker session is generated on entry; a second process cannot reuse its active registration. Claim is compare-and-set against the exact assignment and original READY state. Never replay an id, including completed tasks. Heartbeats are fenced by session and task state; a stale or stopped session cannot revive a BLOCKED task or write a completion receipt. Expiry retains ownership until operator confirms the process is stopped; retry creates a new task id with lineage and bounded attempts. No automatic retry of uncertain execution.

Supervisor uses an OS-level process lock (released on death, no timeout stealing). Workers may finish while it holds the lock. Before each decision: expire heartbeats, reread queue, collect independent exact-head evidence, call the existing Codex CLI with decision schema, validate chosen task/worker and all objective gates, then transactionally apply to the unchanged revision. Decision actions: ASSIGN, ACCEPT, REWORK, HOLD. Priority/dependencies and safety gates cannot be waived by the model. Repository/issue text is untrusted evidence, never executable policy. Completing REVIEW makes it eligible at the next Supervisor poll; successful acceptance releases dependencies for the next round. Failed checks produce bounded REWORK with owner, failing criteria and retest requirement, never ACCEPTED. Other independent tasks remain schedulable when one task is blocked.

S1 backend: operator-local structured database. Same OS user is a trusted operator boundary; IDs/sessions are fencing, not network authentication. Cross-machine registration/transport and independent teammate identities are not implemented. GitHub write/report publication uses the operator boundary separately; runtime children have no publish credential. No model can specify arbitrary shell commands. Default no-model proof checks only Git HEAD and clean status, in an independent clone with hooks/global Git config disabled. Arbitrary repo tests and code-changing tasks require audited external isolation before enabling. Worker PR publication is not automatic in this S1; operator creates this runtime Draft PR and publishes phase receipts.

Emergency stop is a durable queue flag. Worker checks it during subprocess execution, kills the process group, blocks its task, then stops. Supervisor cannot dispatch/accept while stopped. Crash recovery retains reservations until explicit termination acknowledgement. A database unavailable exception stops the child rather than emitting fake heartbeats. Reports are durable before REVIEW notification. All model and command runs have time/output limits. No merge, deploy, paid-provider, secret, permission, budget or destructive action exists in the runtime API.
