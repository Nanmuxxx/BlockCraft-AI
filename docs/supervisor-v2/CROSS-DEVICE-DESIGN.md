# Cross-device design only — NOT_IMPLEMENTED

Gate: implement a remote broker only after real single-device Worker→independent QA→ACCEPT/REWORK→next-task proof. No public listener, credentials, shared database, service deployment or permission changes are created by this design.

Each device runs a local Worker with its owner's local Codex/ChatGPT login. Login files, keychain records and API tokens never travel to the broker or another member. Operator-provisioned device identity is separate from Codex auth. Proposed transport: outbound HTTPS with verified server certificate and separately provisioned device identity (mTLS or short-lived scoped credentials); private/VPN pilot first. Owner/security approval is needed before provisioning identities, hosting or access scopes. The controller's GitHub publishing identity stays outside task processes.

The central database is authoritative. Supervisor alone assigns task_id, worker_id, base_sha, scope, dependencies, acceptance contract and epoch. Worker polls only its own assigned queue, then atomically compare-and-sets READY→CLAIMED against assignment/epoch; it never races for unassigned work. Database transactions enforce one live claim and conservative overlapping path ownership. Require a per-device monotonic request sequence and idempotency key; duplicate requests return the prior result without reexecution.

Heartbeat reports assignment epoch, worker/session, phase and last command timestamp. Server uses its own receive time/TTL. Disconnect/sleep becomes OFFLINE/BLOCKED, never DONE. Expiry retains file ownership until old process termination is independently established; recovery creates a new bounded attempt/epoch. Old epochs cannot heartbeat, submit receipts or revive tasks. Loss of Supervisor authority also stops new dispatch. Emergency stop is durable, versioned, acknowledged by devices, and propagated during running commands; devices fail closed if they cannot maintain the control lease. Local kill must include the whole reviewed execution boundary, not just a parent PID.

Receipt upload is immutable and bounded: task/Worker/session/epoch, exact base/head/test SHA, command argv/exit codes/times, classification, artifact hashes and object-store references. Server checks TLS identity matches assigned worker, epoch, replay/idempotency, schema and size, and recomputes artifact digests. It then independently fetches exact Git objects and reruns allowed checks in a fresh QA environment. Worker signatures/hashes do not prove correctness. CI must name the exact reviewed SHA; missing/failing/changed-head evidence prevents ACCEPT. No code-PR acceptance until required CI/security checks and safe test isolation exist.

Acceptance and rework are transactional, audited Supervisor decisions after independent model QA. ACCEPT releases satisfied dependencies and triggers the next safe assignment. REWORK creates a bounded task with owner, failing criterion and retest requirements; lineage resolution must be designed/tested so unrelated child acceptance cannot silently satisfy rejected original requirements. Approval holds affect only dependent operations; safe disjoint work continues. No merge/deployment endpoint is proposed.

Before rollout: two independently provisioned devices; disjoint simultaneous claims; duplicate/replayed requests; scope collision; stale epoch; dropped connection; sleep/resume; controller crash; oversized/tampered receipt; exact-SHA mismatch; failed CI; emergency stop; timeout; failed recovery; credential-read/exfiltration probes with synthetic values. Evidence must distinguish native processes, real model inference, MOCK protocol tests and actual cross-device authentication. Local SQLite is not copied to network shares or used as a distributed authentication service.
