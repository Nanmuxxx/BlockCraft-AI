## 现状与根因结论

已有 form/list/gallery/metric 统一命令、确定性模拟、版本校验、预览、原子确认、完整撤销及项目 ZIP。本次复用这些实现，不建立另一套执行器。

历史主动建议 `502 / AI_INVALID_RESPONSE` 的具体根因仍未知：当时没有结束原因或分阶段证据。本次确认并修复的是可观测性、错误分类、修改范围防护与重复请求缺口，不能以离线成功推断历史模型回复内容。

“只给表单增加可选字段”扩展的是共享实体 schema，其他绑定积木可读取新结构，但兄弟列表的 fieldIds 和配置保持原样。旧预览把共享结构影响列为受影响积木，容易误解为同时修改列表。现在明确展示必要联动、保留的记录数量，以及只有实际字段配置行所指积木改变显示。

## 实施与处理规则

- 模型失败诊断仅输出 event/channel/stage/reason/finishReason 枚举；未知结束原因归 unknown，未获得则 unavailable。禁止原始回复、提示词、ID、业务记录、任意错误文本或凭据。诊断 sink 故障不影响安全拒绝。
- body、envelope、content、advice、candidate 分阶段拒绝；保留严格 schema、引用、命令、能力、版本绑定、权限及原子执行校验。截断、拒绝和工具调用不被修复成合法计划。
- 主动建议提示词改为最多 3 条短建议，明确输出长度；可执行建议包含具体操作、字段名和定义。未扩大 token 预算，未引入自动重试或付费回退。
- 浏览器/服务端采用相同的保守中文意图守卫。无法识别、否定或多选指令提前请求澄清，服务端在预约额度和模型出口前拒绝。新增字段必须单个、可选、名称明确、类型符合明示要求，保持原有显示字段与顺序，仅追加新字段。禁止顺带修改展示、增删或排序。
- 显示/隐藏必须对应明确字段名称及动词，不能顺带隐藏、恢复或重排其他字段。“删除列表中的记录”不授权删除列表积木；明确删除类型与当前选择不符要求澄清。指标聚合与明示操作一致，切换数值字段须指明字段名；图库隐藏/清空、恢复方向不能反转。
- 浏览器回归发现旧指标名“报名人数”与目标“数量合计”被误认为相互矛盾的聚合要求。已限定转换句式只校验转换动词后的目标；离线覆盖原句、反向聚合、矛盾目标及重复转换，未放宽命令或配置校验。
- 展示属性仅允许用户提及的键。新增积木类型必须明确，排序继续受 Host 选中范围与完整顺序校验。
- 格式错误、超范围、需澄清、版本过期、非法配置、权限、额度、服务中断与超时使用不同固定中文反馈，不显示上游任意 message。
- 同一在途指令重复提交返回 AI_BUSY，预览阶段重复提交复用原计划；重复确认沿用既有幂等提交。失败后用户主动重试只增加一次新尝试，取消或迟到响应不能写入。
- Docker allowlist 与最终运行时补齐 mochi-response/errors/intent 模块，沿用镜像内 ESM 遍历检查。
