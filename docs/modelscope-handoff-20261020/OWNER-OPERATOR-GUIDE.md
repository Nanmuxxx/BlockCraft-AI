# 给负责人的首次无密钥部署最少操作指南（审批前仅阅读）

目标：`https://www.modelscope.cn/studios/Nanmuxxx/BlockCraft-AI-Fullstack`。

此指南仅用于 Supervisor/Tech Lead 选定本备份包后的一次无密钥离线 Demo 部署。当前无上传/部署授权。若已有郑相包上传或平台 commit，请先由团队核对该包；不要重复上传本备份包或覆盖平台内容。当前此备份包的技术检查不能代替另一包的检查。

## 负责人一次性审批范围

建议审批文字由 Supervisor 给出，明确：精确源 SHA、选定包 SHA256、目标 Studio、首次上传/构建/无密钥启动、免费 CPU 资源范围。该授权不包含真实 AI、Secret、付费调用、付费算力、修改权限或未来版本切换。任何平台提示收费/额外权限时暂停并报告。

## 批准后只需负责人操作的平台步骤

1. 登录目标空间。由平台实际页面确认自己具有管理权限，确认当前使用 Docker SDK；不要创建第二个空间，也不把未部署页当成故障日志。
2. 在「空间文件」查看当前内容。若已经存在 commit/代码，截图/记录 commit 给团队，先核对唯一候选；不要盲目删除。若确认为空且选定本备份包：下载并解压 `BlockCraftAI-main-4a95cae-source-only.zip`，打开解压目录后应直接看到 `Dockerfile`、`ms_deploy.json`、`src`、`server`、`public`。
3. 在任何平台文件写入前，先只读确认登录后的目标页面是否支持完整目录递归上传，并能保留隐藏文件 `.dockerignore`。网页目录上传、ZIP 自动解包及隐藏文件保留目前均为 `NOT TESTED`，不得假设具备能力。只有页面实际确认支持且另有单独上传/部署授权后，才上传已解压目录中的内容；不要只上传 ZIP，也不要额外嵌套一层文件夹。若能力不支持或无法确认，停止文件操作，团队再依据实际页面核对 Git 传输步骤。
4. 上传完成后团队核对根文件和平台 commit。平台 push/上传可能立即触发构建，所以这一动作本身就需已有批准。若平台要求手动启动构建/部署，按实际页面执行一次；按钮名依页面实际显示，不假设某个固定标签。
5. 配置保持 Docker，端口 `7860`；已有 Dockerfile 自动执行构建和 `node server/index.mjs` 启动，无需填写 Vite dev/preview 命令。资源只选已批准的免费 CPU；如 Docker 需要账号绑定/实名，以 Owner 自己的平台流程完成，Agent 不接触账号凭据。
6. **Secrets 保持不配置**。不填写 `DEEPSEEK_API_KEY`，不设置真实预算、session 或付费开关。无需为预期生成401错误“修复”密钥。此版本仅验证平台离线 Demo。
7. 首次构建结束，把页面显示的状态、平台 commit、应用访问链接和脱敏构建/启动错误（若有）交给 Supervisor。无需在首次构建前提供不存在的历史日志。
8. 团队负责公网 QA：负责人只需保持登录可处理必要平台操作，不承担代码/容器排障。QA 通过后再冻结该首个可用版本。

## 成功与失败

成功至少需要真正实例可访问，health200、页面资源和 B/C 离线番茄钟可操作；生成接口保持401、Mochi在线能力disabled。平台“构建成功”本身不等于公网 QA PASS，也不等于真实 DeepSeek 交付。

失败时保留本次日志和 commit，不注入密钥尝试修复，不换付费资源，不修改启动命令，不覆盖稳定工作区。首次上线没有旧公网版本可回滚；由团队在隔离候选中定位后提交新的精确修复及审批。后续真实 AI 属独立高风险升级，必须先完成安全审查、费用/调用限制方案并获负责人明确批准。
