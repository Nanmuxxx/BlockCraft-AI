## Ownership protocol

All admissions, state writes, status callbacks, cancellation initiation and terminal clears in `http.ts` now use the same per-project **exclusive Web Lock**. Each callback re-reads persistent state *inside* the lock and compares its immutable request ID and known job ID. A stale operation throws IMAGE_OPERATION_SUPERSEDED without shared mutation or candidate return. The UUID is created only after admission obtains that lock and finds no unresolved state. localStorage by itself is not used as a compare-and-swap; [Web Locks](https://www.w3.org/TR/web-locks/) serializes its synchronous critical sections across same-origin tabs. Network requests never hold the lock. No lock stealing or lease expiry can authorize a new dispatch.

The existing version-1 opaque-ID record is preserved across refresh/remount; no migration deletes existing debt. PENDING/UNKNOWN/UNCERTAIN all deny new admission. UNKNOWN/abort cannot downgrade UNCERTAIN. Storage read/parse/write/remove failures, missing or rejected coordination, and lock acquisition exceeding 2 seconds fail closed. Failed cancellation never proves termination. Only a matching authorized status GET with SUCCEEDED/FAILED/CANCELLED and charge NONE may remove that operation's record, under the same exclusive lock. A successful create response alone does not clear it. Missing IDs, 403/404, network failures and UNCERTAIN never clear it. Reconciliation does not adopt a candidate, save a project or retry.

Controller protection follows the provider capability even if its caller supplies source=MOCK. Candidate publication and confirmation check unresolved HTTP state. The fixture panel subscribes to review state even when another source is selected, so another tab's HTTP lock restores the HTTP warning and disables source switching.

Files changed are restricted to the authorized gallery provider/controller/panel, HTTP test and HTTP integration tests. No server/image-generation code, workflow, production routes, auth/ledger, keys, permissions or budgets changed. Existing CI already invokes the extended `rework.browser.cjs` at 1440 and 390 and the contract glob, so all new tests enter CI without changing gates.
