# Proposed image coordinator — NOT IMPLEMENTED

Proposal published before code edits: [#92](https://github.com/Nanmuxxx/BlockCraft-AI/issues/92#issuecomment-6445068279). Workshop confirmation pending. Nothing in this document changes existing ProjectAsset/ZIP/browser interfaces or authorizes spending.

## Identity and request boundary

Future authenticated `POST /api/image-generations` takes exactly `{projectId,prompt}` plus exactly one 32–128-character `Idempotency-Key` matching `[A-Za-z0-9_-]`. Proposed body cap 8 KiB, prompt 1–500 UTF-16 code units / <=2000 UTF-8 bytes; reject unknown fields, controls, invalid UTF-8, duplicate headers and malformed JSON. Clients cannot choose provider, model, quality, dimensions, n, endpoint, price, user or approval. Bound body/auth reads and reject before reservation.

Trusted server session resolves principal; project authority independently resolves `canGenerateImage(principal,projectId)`. Local workspace IDs and browser `WriteAuthorization` are not proof of remote membership. Auth timeout, missing/revoked session, unknown project, authority outage and policy expiry fail closed. For cookie auth, require configured exact Origin plus CSRF protection; Origin alone never authenticates. Check project permission again at egress and when returning a cached candidate; deny revoked access. Provider receives no cookie, session token or browser authorization.

Future wire success: one sanitized PNG candidate (data URL, MIME, actual dimensions/bytes, opaque requestId, `source: MOCK|REAL`) within existing caps. Do not return remote signed URLs, credentials, raw provider errors, revised prompt, headers or untrusted metadata. No generated image auto-adopts into a project. Workshop retains candidate preview, discard, explicit adoption and transactional persistence. A future switch from data URL to asset handle requires a separate acknowledged contract.

## Persistent cost and idempotency state machine

Use one transactional store across processes/worktrees and all image consumers. Store server-derived principal/project scope, hashed canonical request and key, policy/approval ID, model/version/region, integer currency units, pinned price hash/expiry, timestamps, status and bounded candidate reference. Never store raw prompts, signed URLs, cookies or keys in audit logs. Scope a unique claim to `(principal,projectId,key)`; hash includes canonical prompt plus **server-selected** provider/model/size/quality/policy. Same key/different hash => 409. Same hash pending => bounded status/poll response, no second egress; completed => validated cached result after auth; ambiguous => no retry. A new key is still subject to project/user/global budgets.

Admission transaction: lock/update global/day + user/day + project/lifetime balances and claim together; check finite integer arithmetic, currency equality, policy freshness, concurrency and worst-case reserve; commit durably **before** network. Never debit three separate stores with partial-success refunds. Missing/corrupt/rolled-back store, lock contention, uncertain lease ownership, clock rollback and exhausted capacity deny. Restart must retain debt and claims; TTL must never erase an unresolved reservation. Daily rollover uses server UTC windows and keeps previous unresolved debt encumbering the overall allowance; restart/rollover cannot mint new money. Project lifetime cap prevents daily resets bypassing it.

States: `RESERVED -> DISPATCHED -> SETTLED` with a separate result-validation status. A pre-dispatch abort may release reservation only after a durable proof that no network dispatch occurred. After dispatch, disconnect, timeout, transport exception, missing usage, unreadable response or crash yields `UNCERTAIN`, retains full reservation and halts new paid dispatches in the affected approval scope. No SDK retry, application retry or provider failover. A fenced single-dispatch lease prevents a late worker sending after another process assumes ownership. A cancel request aborts local work but is not proof of provider cancellation/refund. Owner reconciliation is required to resolve unknown spend.

Known trustworthy charge can settle even when image validation fails; **invalid output does not refund paid compute**. If cost exceeds reservation or usage/price cannot be trusted, halt; never silently cap recorded spend at the estimate. Commit settlement and replayable sanitized candidate atomically, or retain a settled-charge/result-unavailable record that forbids regeneration. Cache write failure cannot justify a second paid request. Result retrieval is authorized and bounded. Test corruption, process kill at every transition, repeated/reordered requests, contention and disk-full conditions before claiming durability.

## Transport, image validation and errors

Future server-owned allowlisted HTTPS endpoint, TLS verification, redirects disabled, n=1, no streaming partial images, no reference-image uploads/search/tools initially. Deadline proposal: connect 10s, total job 120s; UI needs a matching acknowledged deadline or asynchronous job flow (current controller is 10s). No latency SLA inferred. Cancellation must bound uncooperative transports and discard late bodies without publishing success. Shared concurrency initially 1 per approval plus 1/user and 1/project; admission queues bounded or rejected.

Bound JSON and binary streams before accumulation (proposed 12 MiB transport envelope / 8 MiB raw image, not a client upload entitlement). Validate base64 canonically before allocating decoded data, provider envelopes and success count. If supplier returns a download URL: fixed documented HTTPS host allowlist, no credentials forwarded, DNS/private/link-local/loopback protection on every connection, no redirects, bounded streaming, no URL persistence/logging. A hostname suffix test alone is insufficient SSRF protection.

Decode in a resource-limited process using a maintained decoder, verify actual raster dimensions and reject animation, truncation, malformed chunks and decompression bombs. Proposed raw cap 4,194,304 pixels (stricter than current frontend's 16,777,216); normalize to <=512×512 static PNG, strip unnecessary metadata, then enforce <=524288 decoded file bytes and <=699100-character data URL. Reject an oversized normalized PNG; never regenerate automatically. Fixed Mock fixture tests do not validate this decoder pipeline. Content safety must be reviewed for children's use; retain supplier safety controls, reject safety blocks, add application output review as needed, and return generic user-facing errors. Do not weaken moderation to improve success rate.

Proposed stable errors: 400 INVALID_INPUT; 401 UNAUTHORIZED; 403 PROJECT_FORBIDDEN; 409 IDEMPOTENCY_CONFLICT/IN_PROGRESS; 429 BUDGET_EXHAUSTED/RATE_LIMITED; 503 IMAGE_DISABLED/AUTHORITY_UNAVAILABLE/LEDGER_UNAVAILABLE/PRICE_UNVERIFIED/SPEND_UNCERTAIN; 504 DEADLINE_EXCEEDED; 502 INVALID_IMAGE/PROVIDER_UNAVAILABLE; moderation => generic blocked result. Exact transport status mapping needs Workshop ACK. Never label a dispatched timeout safe-to-retry. No raw provider text in public messages or logs.
