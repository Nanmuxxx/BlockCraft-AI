## Separate execution surfaces

CustomBlock is not mounted by baseline server/index.mjs. Its source closure is server/custom-block/{generator,provider,store,protocol,contract,policy,import-policy}.mjs plus ai-abort, generated custom-block CJS index/json and their transitive generated modules. Build uses server/custom-block/{build-protocol.mjs,tsconfig.json} and src/custom-block/**/*.ts, writing .generated/package.json with type=commonjs. import-policy requires typescript at runtime. live-generate.mjs and install-export.mjs are separate CLI entrypoints. Do not accidentally enable their paid CLI or package it as a new HTTP endpoint. These sources/generated outputs/TypeScript are not currently packaged for runtime; only a future explicitly approved CustomBlock server mount would make them runtime requirements.

ZIP is a separate local Vite surface: vite.config.ts -> server/project-export/vite-plugin.mjs -> local-http.mjs -> dynamic tools/project-zip-export/export.mjs on admitted local request. Docker's build includes project-export for Vite configuration. Production server/index.mjs does not mount that handler. Absence of ZIP tooling from production runtime is not a startup defect; preserve local-only isolation and v2 refusal.

Startup imports access.mjs, egress.mjs, provider.mjs and pricing.mjs; explicit paid transport construction additionally requires ledger.mjs. All use Node builtins, no npm runtime package or static asset. At minimum server/paid-gateway/** must be admitted by .dockerignore and copied into both stages if imported from the production entry. Include every relative imported file plus any runtime assets/package dependency; verify the final closure with the audit after integration.
