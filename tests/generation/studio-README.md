# Studio composition candidate — Mock only

Base: `b2063e7c6ca83b55557924279501b2b6e9f2b158` (Draft PR75).
Only new launcher and `tests/generation/studio-*` files are owned by this patch.
No Gateway, policy, local-owner, Docker, real secret or real ledger changes.

`startStudioServer` composes the existing `startServer`, principal paid runtime,
opaque resolver and fixed production `POLICY`. It passes HTTPS `publicOrigin`
explicitly to `createAppServer`. The ledger lock and existing shutdown drain are
retained. Neither Origin, XFF, client principal nor environment flags grant access.
Every generation request requires one exact Origin and a preprovisioned opaque
session. Revocation/expiry and private approval validity are rechecked per request.
No cookie, token, key or login response is generated by this launcher.

## Owner-only provisioning contract (NOT deployment instructions/approval)

The trust root is an independently reviewed Owner-controlled private POSIX
directory, canonical absolute path, owner UID matching the process, mode0700.
No directory/key/approval is created by the launcher. Private files must be
regular mode0600 files, same UID, single link, canonical paths; no symlinks.

- `STUDIO_APPROVAL_PATH`: absolute path of an Owner-provisioned JSON approval
  inside that directory. A path or environment flag alone grants nothing.
- `PUBLIC_ORIGIN`: exact HTTPS origin matching the approval, no trailing slash.
- `DEEPSEEK_API_KEY`: separately approved server-only injection; not in approval.
- `binding.key`: pre-existing 32 random persistent bytes, kept across restart.
- `studio-ledger.json` and sidecar/locks: exclusively reserved Gateway state in
  the same private persistent directory. Never delete/reset to unlock or renew
  budget. Production profile and unmodified POLICY are always used.

Approval JSON has exactly these properties (placeholder values are not valid):

```json
{
  "version": 1,
  "publicOrigin": "https://studio.example",
  "policyId": "EXACT_EXISTING_POLICY_ID",
  "approval": {
    "providerVerified": true,
    "permissionsVerified": true,
    "reference": "INDEPENDENT_OWNER_APPROVAL_REFERENCE",
    "maxCalls": 3,
    "expiresAt": 0
  },
  "sessions": [{
    "sessionHash": "SHA256_OF_INDEPENDENTLY_PROVISIONED_OPAQUE_TOKEN",
    "principal": "stable-owner-principal",
    "appId": "pomodoro",
    "expiresAt": 0,
    "revoked": false
  }]
}
```

Approval must be unexpired and not outlive the fixed pricing snapshot; maxCalls
and policyId must exactly match POLICY. Session expiry cannot exceed approval.
Principals and hashes are unique. The actual request cookie is resolved by the
existing opaque resolver. App/session scope comes only from this configuration.
Changing approval requires restart; removing/revoking/expiring it denies requests
immediately. Trusted Owner config can update sessions; no public provisioning API.

## Explicit remaining blockers

- **Secure cookie issuance NOT IMPLEMENTED**: no anonymous bootstrap endpoint,
  no `/local-owner/start`, no access-code login. Owner must independently review
  a trusted authenticated issuer setting only `__Host-bc_session`, Secure,
  HttpOnly, SameSite=Strict, Path=/; token must not enter URL, response body or
  logs. Preprovisioned cookie is the Mock integration boundary, not public login.
- TLS terminator, exact external origin routing and backend network isolation
  remain platform assumptions. Listener defaults to loopback. No XFF trust or
  direct HTTP public access is approved. The module API permits explicit host/port
  for a separately reviewed integration; CLI keeps loopback3001.
- Platform must prove one process/replica, durable private POSIX volume with
  exclusive create/atomic rename/fsync, secure Owner file provisioning, stable UID,
  persistent key/ledger and no untrusted same-UID writers. File mode does not prove
  provenance or persistency. Launcher cannot independently attest these facts.
- Runtime directory must be outside served static assets and untrusted uploads.
  Secrets, allowlists, ledger and binding key must never be exposed through proxy,
  static server, logs, images or shared mounts.
- Real paid call, production enablement, deployment and merge are NOT authorized.
  No browser/PUBLIC/real DeepSeek acceptance is claimed for this patch.
