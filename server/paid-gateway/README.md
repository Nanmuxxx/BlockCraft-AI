# Controlled Phase 2 DeepSeek gateway

Only the explicitly authorized operator may run `node tools/real-deepseek/evaluate.mjs --live`. The ordinary server has no generation identity adapter and denies legacy v1 and v2 before Provider access. Origin/CORS never grant identity. The local evaluator generates a random 256-bit bearer token, keeps it in server memory, and injects it only in its server-side loopback Vite proxy. No token or API key enters the webpage bundle, URL, report or Git. No proxy listener is exposed beyond IPv4 loopback. Mochi remains disabled and CustomBlock native egress is blocked. Trusted injected transports are server-code configuration, not a browser-controlled permission.

The evaluator reads the existing primary repository `server/.env` in process, never prints its content, and uses only `DEEPSEEK_API_KEY`. It fixes model `deepseek-flash` and the official HTTPS completion endpoint. It does not modify production or Docker configuration. Never deploy this local evaluator/proxy as a public service.

Pricing verified 2026-10-19: https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ . Peak cache-miss input ¥2 / million tokens, output ¥8 / million. Cache/discount savings are ignored. Thinking disabled, JSON mode, max_tokens <=8192, no tools, retries=0, redirects rejected, concurrency=1, timeout <=30s. The pricing snapshot expires before the next day; later use requires explicit re-verification.

One canonical private ledger under the common workspace parent is shared across worktrees. Atomic fsync-before-network reservations and an exclusive process lock protect it. Crash leases are never automatically removed; an incomplete/uncertain call halts the ledger. Missing, corrupt or over-bound usage halts automatic calls. All reservations remain charged to the internal allowance even after trustworthy cheaper usage. Audit retains only request hash, time, model pricing, reservation, usage and estimated cost; no request text or credentials.

User authorization is ¥10 total with ¥8 auto-stop. This implementation is more conservative: at most ¥1 reserved and six attempts, and never reserves across ¥8/¥10. Input reservation uses UTF-8 bytes plus 8192 framing tokens; this is a conservative software bound, not a tokenizer proof or supplier-side hard spending limit. Usage is checked against the reservation. Software cannot control supplier price changes, provider accounting defects, other account users or arbitrary code bypassing this trusted runner. No claim of a supplier hard limit is made. Unknown results stop rather than refund/retry; operator must reconcile the provider account before any future authorization.

Offline tests never read `.env`, never call the native network transport and use separate temporary ledgers. Persisted real responses are allowlisted and scanned; only AppSpec JSON is interpreted by the existing strict validator and trusted renderer. Generated TSX is never executed.

## Model/configuration contract (integration owner handoff)

Paid composition MUST explicitly supply `model: PRICING.model` (`deepseek-flash` in this dated price snapshot) to `createAppServer`, and to any separately authorized Mochi/CustomBlock Provider. Supply the exact same `fetchImpl` returned by `createPaidTransport` and canonical shared ledger; do not construct a ledger per consumer. The entry also requires `generationAccess` (default deny); v2 additionally requires its existing admission gate. Provider identity/configuration does not replace endpoint authentication. CustomBlock additionally requires its existing explicit `allowPaid` gate. This contract does not authorize enabling those features or executing generated TSX.

Historic defaults (`deepseek-v4-flash`) and offline legacy configurations are preserved. They deliberately do NOT imply gateway compatibility or paid authorization. Do not rely on the default or merely inject a gateway while leaving the model unspecified. The gateway accepts ONLY the exact price-snapshot model, rejects old aliases before reservation/network and never silently rewrites them; selecting an arbitrary DEEPSEEK_MODEL cannot change its price approval. CustomBlock's construction allowlist includes exact `deepseek-flash`, while older names remain available only to explicitly trusted offline adapters. The snapshot expires at its recorded time; this patch does not extend it, raise any cap, reset the canonical ledger or approve more real calls.

`requireControlledEgress` is a guard against accidental direct use of the captured native fetch. It is NOT a sandbox or proof that every injected function is budget-controlled: arbitrary injected functions (including wrappers around native fetch) are trusted server code and can bypass it. The audited path requires the exact branded `createPaidTransport` instance; `isPaidTransport` is provenance, not endpoint authorization. Browser requests cannot inject a transport; anyone able to modify server code can also remove guards. Do not claim protection from malicious server code. Public/multi-user production authentication and Docker packaging remain unimplemented/BLOCKED; this document is an integration contract, not a deployment approval.

Offline evidence: `tests/paid-gateway/model-contract.test.mjs` rejects both old aliases through all three consumers with zero reservations/network, then composes all three with the exact priced model and one shared six-call audit ceiling. Synthetic CustomBlock output remains inert text. The monetary ceiling, cancellation and unknown-usage halt remain covered by the eleven independent security tests. No live calls are used.

## Phase 3 per-request synchronous admission

The separate, default-off plan handler must verify both `isPaidTransport(transport)` and `supportsPaidAdmission(transport)` (independent private WeakSet membership), acquire a server-owned lease, and call `transport(url, init, { assertCurrent: () => lease.assertCurrent() })`. Do not pass a bare method if it depends on `this`. The handler owns `lease.release()` in finally. The gateway captures the function before any await and accepts only the literal synchronous result `true` twice: immediately before `ledger.reserve`, and in the network microtask immediately before invoking `fetchImpl`, with no await between that final check and invocation. Missing/non-function, false, thrown errors, Promise and thenable results fail closed. A rejected native Promise is consumed without authorizing anything. No guard, lease or permission can be supplied through request JSON/headers; unknown body keys remain rejected.

`createPaidTransport({ ..., requireAdmission: true })` additionally rejects omission on every request for that instance. It defaults to false for the established v1 server-code contract; this does not authorize a new public route. Even in legacy mode, supplying a third argument always validates and enforces it. Phase 3 must enforce its lease contract on every request and gate on capability so an older transport cannot silently ignore the extra argument. Plain properties, wrappers and arbitrary functions do not acquire the capability brand. Prefer one shared transport/canonical ledger, not new per-route instances.

The lease is trusted synchronous server authority, not an asynchronous check cached as a boolean. It must read/hold the actual current session, subject, owner, project revision/instance/selection and signal. `supportsPaidAdmission` proves gateway support, not correctness of an arbitrary lease. The no-await boundary covers in-process scheduling; cross-process or distributed authority needs a proper authoritative lock/lease or equivalent atomic guarantee in the trusted adapter. No sandbox against malicious server code, no rollback of already-sent network calls or arbitrary callback side effects is claimed. Plans remain data and require independent host owner/CAS confirmation.

### Proven not-sent reservations

An invocation-local `sent` flag becomes true immediately before calling `fetchImpl`. Once invoked, even a synchronous throw or unknown connection failure retains the full monetary reservation and halts if usage is uncertain. Trustworthy settled usage likewise never receives a refund. Only an exception/cancellation/revocation before fetch invocation may durably transition `reserved` to `not-sent` using `ledger.notSent(id)`. This trusted-ledger operation is not an HTTP API. It preserves original `reserveNano`, request hash and attempt, records `releasedNano === reserveNano` and `estimatedNano === 0`, omits usage, and releases money without restoring attempt capacity. Duplicate release/settled/uncertain release is rejected.

Effective retained money is `sum(entry.reserveNano - (entry.releasedNano ?? 0))`; attempts remain `entries.length`, capped at six including not-sent attempts. Do not call every ledger entry an actual network call. Reopen validates releases strictly and permits terminal not-sent entries; unresolved reserved/uncertain entries still halt. Existing version-1 entries without releasedNano remain compatible and fully retained. Older gateway code rejects the new not-sent status, so downgrades fail closed. Never reset/delete/recover the canonical ledger or a crash lock to regain capacity. Persistence failure leaves the ledger unavailable; crash before durable not-sent recording conservatively retains the reservation. Prices, expiry, monetary ceilings and max attempts are unchanged. All new evidence uses temporary synthetic ledgers and injected transports; no real call was made.
