With the full configured input bound, three worst-case reservations total ¥0.49152. These are software reservations, not provider-enforced billing caps.

Core's principal path imports `createPrincipalPaidGenerationRuntime` from `server/paid-gateway/runtime.mjs` and calls it with `{ env, bindingKey, policy, profile }`. `profile` defaults to `production`; the isolated candidate must explicitly pair `{ policy: SMOKE_POLICY, profile: 'local-smoke' }`. A mismatched pair is rejected before egress. The runtime returns `{ policy, model, forRequest, close }`; `forRequest({ principal, idempotencyKey, payload })` returns `{ apiKey, model, fetchImpl }` for exactly one identity-bound request. Core resolves trusted identity and request admission before calling it, passes `fetchImpl` and `model` to its existing provider composition, and maps `paidGatewayHttpStatus(error)` to HTTP status. The gateway owns the only durable reservation; Core must not debit a second budget. Call `runtime.close()` only after graceful request draining.

`createPaidGenerationRuntime({ env, fetchImpl, onResponse, timeoutMs })` is the isolated smoke transport factory for offline Mock verification. It returns `{ fetch, ledger, policy, model, close }`. It is not a Core identity integration API and does not authorize live calls by itself. Both factories read the key only from the supplied trusted server-side environment and never return or log it.

The factory does not create an HTTP listener or resolve identity. The local launcher must bind the application to `127.0.0.1` only and require the constant-time bearer/loopback access check (`createLocalAccess`); do not forward this route through a Vite proxy, tunnel or public interface. Identity and admission exceptions must map to deny. Core must map Gateway failures through fixed sanitized HTTP statuses and never include provider bodies, credentials or raw exceptions.

Never point this profile at the old canonical production ledger. It requires a dedicated private POSIX directory and separate v2 `local-smoke` ledger; profile/approval mismatch, expiry, missing or corrupt state, unresolved reservation, unknown usage, timeout or disconnect fails closed. Use one process only. Stale locks are not automatically recovered. Do not edit, reset or delete an existing ledger. This candidate does not authorize merge, deployment, public access or testing beyond the owner's separately approved local run.

## Model/configuration contract (integration owner handoff)

Paid composition MUST explicitly supply the runtime's exact `model` and per-request `fetchImpl` to Core's existing app server/provider composition. Do not open another ledger or create another reservation owner. The entry requires a trusted principal resolver (default deny); v2 additionally requires its existing admission gate. Provider identity/configuration does not replace endpoint authentication. This contract does not authorize executing generated TSX.

Historic defaults (`deepseek-v4-flash`) and offline legacy configurations are preserved. They deliberately do NOT imply gateway compatibility or paid authorization. Do not rely on the default or merely inject a gateway while leaving the model unspecified. The gateway accepts ONLY the exact price-snapshot model, rejects old aliases before reservation/network and never silently rewrites them; selecting an arbitrary DEEPSEEK_MODEL cannot change its price approval. CustomBlock's construction allowlist includes exact `deepseek-flash`, while older names remain available only to explicitly trusted offline adapters. The snapshot expires at its recorded time; this patch does not extend it, raise any cap, reset the canonical ledger or approve more real calls.

`requireControlledEgress` is a guard against accidental direct use of the captured native fetch. It is NOT a sandbox or proof that every injected function is budget-controlled: arbitrary injected functions (including wrappers around native fetch) are trusted server code and can bypass it. The audited path requires the exact branded `createPaidTransport` instance; `isPaidTransport` is provenance, not endpoint authorization. Browser requests cannot inject a transport; anyone able to modify server code can also remove guards. Do not claim protection from malicious server code. Public/multi-user production authentication and Docker packaging remain unimplemented/BLOCKED; this document is an integration contract, not a deployment approval.

Offline evidence: `tests/paid-gateway/model-contract.test.mjs` rejects both old aliases through all three consumers with zero reservations/network, then composes all three with the exact priced model and one shared six-call audit ceiling. Synthetic CustomBlock output remains inert text. The monetary ceiling, cancellation and unknown-usage halt remain covered by the eleven independent security tests. No live calls are used.
